# Skill: Code Review

## 触发条件
当用户说 "review this file"、"code review" 或 "check this code" 时触发

## 流程
1. 在做出任何评论之前，先完整阅读指定文件
2. 按以下标准评估代码：
   - 正确性：代码是否做了它声称要做的事
   - 安全性：是否存在注入漏洞、暴露的密钥、或不安全的操作
   - 性能：是否存在明显的低效或 N+1 查询模式
   - 可读性：代码是否清晰、命名是否合理
   - 边界情况：哪些输入或状态可能导致失败
3. 按严重程度组织反馈：
   - CRITICAL：上线前必须修复
   - IMPORTANT：应尽快修复
   - SUGGESTION：有此修改会更好
4. 对每个问题，提供具体的行号或段落以及建议的修复方案

## 输出格式
按严重程度排列的编号列表。每项包含：问题是什么、为什么重要、如何修复。最后给出总评分（满分10）和一句话总结代码整体质量。
